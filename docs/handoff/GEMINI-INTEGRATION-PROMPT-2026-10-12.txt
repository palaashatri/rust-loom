WORK ITEMS (in this order; each is done only when its acceptance checks pass)

W1. Writer: real table editing in the app
  Make table blocks render and edit as TABLES in the page, not as pipes.
  Suggested design (you may choose another if it satisfies the checks): keep Markdown as the
  storage/migration format; lay the table out with loom_objects::TableLayout using
  loom-fonts for wrapped cell text; draw it as a grid element in the page projection; edit
  the active cell through one editor overlay positioned over the cell.
  Acceptance:
   a. Insert Table (menu + command palette + toolbar Insert menu) with a rows x columns
      choice creates a table with the caret in the first cell.
   b. Tab / Shift+Tab / arrows move between cells; Tab in the last cell appends a row;
      typing is one coalesced undo step; Undo/Redo restore structure.
   c. Insert/delete row and column, merge/split cells from menu + palette; the inspector
      has a table style gallery (12 styles) plus header-row/banded/first-column toggles,
      all live and undoable.
   d. Text typed anywhere around a table never disappears from PDF/DOCX/Markdown export
      (property test over random documents: every non-space character appears in PDF text
      extraction and DOCX document.xml).
   e. DOCX export contains a real w:tbl (grid, shading, merges); open the app-exported file
      in Microsoft Word through COM (hidden) and assert row/column counts and cell text.
   f. Keyboard-only: everything above works without a mouse; the table exposes table / row /
      column-header semantics in the accessibility tree (names like "Table 3 by 4, cell
      B2: text").
   g. Typing in a 100x20 table through the APP callback path (not a core function) stays
      within 16.7 ms p95 at CARGO_PROFILE_TEST_OPT_LEVEL=3.
   h. Screenshots at 1280x800 light/dark/high-contrast and --rtl that you VIEW and describe.

W2. Clipboard: suite interop in the apps
  Wire loom-clipboard into Sheets, Writer and Present.
  Acceptance:
   a. Sheets Copy/Cut writes: private application/x-loom-objects+json, text/html table with
      inline styles (values as displayed, fills, bold, alignment, column widths), image/png
      render (optional), and TSV; Sheets Paste prefers private > HTML table > TSV.
   b. Writer Paste of a Sheets range inserts an editable TABLE block (values, formats,
      widths, fills); pasting HTML tables from Excel/Word/browsers works; plain TSV becomes a
      table when it has tabs on >= 2 rows, otherwise text.
   c. Present Paste of a Sheets range inserts a table element in the slide; pasting a Sheets
      chart (private chart payload) inserts a chart element.
   d. Writer/Present "Copy" of a table writes HTML + TSV + private so it pastes back into
      Sheets as cells.
   e. Real OS clipboards: Windows (CF_HTML offsets correct; verify by reading it back with
      PowerShell [Windows.Forms.Clipboard]::GetData('HTML Format') and by pasting into Word
      via COM), Linux X11 (verify text/html and text/plain with xclip -t). Platforms or
      formats you cannot support must return a typed Unsupported and say so in the status
      line; never fake success.
   f. Hostile input (50 MB, deep nesting, malformed HTML) does not hang or crash.

W3. Present: tables and charts as first-class slide objects
  Acceptance:
   a. Insert > Table (rows x columns) and Insert > Chart (from clipboard payload, or a
      minimal data editor: category/series grid) exist in menu, palette and toolbar.
   b. In-slide cell editing with the same keyboard model as W1 (Tab, arrows, add row at
      end); table style gallery in the inspector; move/resize/delete/undo work on the
      object like other elements; animations apply to the whole object.
   c. PPTX export writes a:tbl and c:chart graphic frames; File > Open .pptx works through
      import_pptx with a warnings dialog listing anything unsupported (SmartArt, media,
      etc.); round trip: export, re-open, compare model equality for tables/charts/text.
   d. Open the exported .pptx in Microsoft PowerPoint through COM (hidden): assert slide
      count, table rows/columns and cell text, chart presence (HasChart) and title.
   e. PDF export draws tables and charts (verify text extraction with qpdf/Ghostscript or
      loom_pdf::inspect).

W4. Writer: open DOCX and embed charts
  Acceptance:
   a. File > Open accepts .docx (picker + drag/startup path); uses import_docx; unsupported
      constructs are listed in a warnings dialog before replacing the current document

   b. Insert > Chart (from clipboard payload) places a chart block that renders in the page
      and exports to DOCX (c:chart part) and PDF.
   c. Round trip an Office-authored .docx fixture (create one with Word COM: headings,
      list, table, bold/italic runs, an image) and assert structure survives.

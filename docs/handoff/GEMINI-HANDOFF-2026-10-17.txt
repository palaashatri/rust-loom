1. WHAT LOOM IS AND WHAT "DONE" MEANS
-------------------------------------
Loom is a local-first Rust + Slint creative suite. v1 scope is three apps on
Windows x86-64 and Linux x86-64 only: Sheets (loom-sheets/), Writer
(loom-writer/) and Present (loom-present/). Shared code is in loom-core/.
macOS and the five other apps (Photo, Motion, Video, Studio, Encode) are out of
scope and locked. Do not touch them except for refactor-only size extraction.

Goal: make Sheets, Writer and Present production ready, with honest evidence.
All three are ACCEPTANCE_BLOCKED today. Nothing is ACCEPTED. A status of
ACCEPTED needs all 14 gates in AGENTS.md section 13 to pass with recorded
evidence. The README of each app must list every working feature first.

5. HOW TO WORK (commands, rules, traps)
---------------------------------------
Build and test per app, from inside the app folder so .cargo/config.toml
applies (Windows needs its 32 MiB stack flag):

  cd loom-sheets && cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace

(same for loom-writer, loom-present). Debug builds only unless measuring
performance. Full suites take 4-15 minutes; run them in the background.

Audits, from the repo root, must stay green:
  python loom-bootstrap/scripts/audit-code-structure.py
  python loom-bootstrap/scripts/audit-ui-foundation.py
  python loom-bootstrap/scripts/audit-governance.py
  python loom-bootstrap/scripts/audit-assets.py

Byte ceilings (loom-bootstrap/contracts/code-quality.toml) are LF bytes and may
not be raised. Sheets app.slint had 19 bytes of headroom (39,713 of 39,732);
Writer app.slint about 780; Present app.slint 42,874 of 42,883. Put new Slint
in a new file or a Slint global exported from an existing file, and new Rust in
new modules, not main.rs.

Method for each feature: write a behaviour test, see it fail, implement, see it
pass, drive the real app, record the evidence. For UI work render with
  loom-<app> --screenshot out.png --size 1280x800 [--theme dark|high-contrast]
  [--rtl] [--text-scale 2.0] [--scale-factor 1.5] [--open file]
and LOOK at the image. The RTL, text-scale and keyboard tab-order tests fail if
a new control overflows a 280 px inspector: fix the layout, not the test.

Traps seen on this project:
 - Slint accessible-role must be a constant: use conditional child elements.
 - Python edit scripts mangled backslash escapes; use the Edit tool for Rust
   string literals.
 - A published number must be measured: say machine, build profile, workload.
 - "Callback exists" or "status string changed" is not proof of a feature.
 - Stale Loom processes hold the recovery lock: use a throwaway HOME /
   LOOM_CONFIG_DIR for live runs, and close windows when done.
 - Do not capture or type into the user's primary monitor (3440x1440). Use the
   vertical monitor (1080x1920 at X=3440, Y=-232 in Windows coordinates).
   Check the foreground window before EVERY synthetic input and abort if it is
   not the Loom window. A reviewer's keystrokes once leaked into another app.
 - The host C: drive filled up once: do not run more than two cargo builds at
   once, never `--release` into a new target dir, never `cargo clean`.
 - GitHub API rate limits intermittently block CI checks; retry later.


6. QA WITH THE COMPUTER-USE SKILL
---------------------------------
Windows: launch the debug or release exe from loom-<app>/target, place the
window on the vertical monitor, drive it with the computer-use tools (or the
PowerShell drivers under .work/w3live/), screenshot only that monitor.
Linux: run the Linux binary inside WSL (distro Ubuntu-E) under WSLg, drive it
with xdotool following .agents/skills/linux-desktop-input/SKILL.md (guarded
X11; Weston ignores windowfocus: launch the target window last or click it).

Walk these journeys and keep the screenshots under .work/<run>/:
 Sheets : new sheet, type values and formulas, drag-select a range, format
          (bold, fill, text colour, wrap), insert chart, sort, copy and paste
          into Writer and Present, save, close with unsaved changes (all three
          buttons), reopen, undo/redo (Ctrl+Z, Ctrl+Y), export CSV and XLSX and
          open the XLSX in Excel (COM) or LibreOffice.
 Writer : type, headings, lists, bold/italic, find/replace, insert table and
          picture (PNG and JPEG), save, reopen, export PDF and DOCX and open
          the DOCX in Word (COM) and LibreOffice, page-break behaviour, undo of
          a picture, window resize across the 1180 px inspector breakpoint.
 Present: new deck, add slides, type in placeholders, style text, change shape
          fill, type geometry, insert table and chart, reorder slides, F5
          slideshow with a transition, presenter view, save, reopen, export
          PDF and PPTX and open the PPTX in PowerPoint (COM).

Also check renders at 1024x720, 1280x800, 1440x900 and 1920x1200, light, dark
and high contrast, text scale 1.0/1.5/2.0, scale factor 1.0/1.5/2.0, and one
RTL pass. Look for clipped labels, overlap, unreadable contrast, lost focus
rings, and controls that do nothing. File every defect with a severity:
  sev1  data loss, crash, freeze, corrupt export, unrecoverable state
  sev2  a primary workflow blocked or wrong
  sev3  cosmetic or secondary
Fix sev1 and sev2 before asking for acceptance.


7. THE ARGON REVIEW (required before any ACCEPTED)
--------------------------------------------------
When you believe one app passes every gate, launch Argon as an independent
hostile reviewer. Give it: the app name, the commit hash, the build commands,
the list of the 14 gates, where your evidence is, and this instruction:

  "Try to make it fail. Open every screenshot yourself. Run the app. Report
   each gate as PASS or FAIL with the evidence you saw, list every defect with
   a severity, and do not accept our evidence without looking at it."

Do not show Argon your conclusion first. If Argon reports any FAIL or any
sev1/sev2 defect, fix and re-review; do not argue the review away.

The ACCEPTED record (in the status table and as a dated paragraph in the
current-truth section) must contain: commit hash, per-gate result with evidence
paths, Argon's name, date and quoted verdict, every disclosed limitation. Update
the app README feature list first. If Argon could not be run, the app stays
ACCEPTANCE_BLOCKED and you say so.

Also update the cards you change in docs/archive/AGENTS-ARCHIVE.md, and update
loom-bootstrap/contracts/workflow.toml and audit-governance.py together if you
change the phase (the governance unit tests fail when the status table and the
contract disagree; a Gemini edit broke them once).

# Design Tokens

The token architecture for Loom. `tokens/loom.toml` is the canonical machine-
readable source; this document defines the naming convention, the layer
architecture, the mapping to Slint constants, and the full token table.

## 1. Architecture

Tokens exist in two layers:

1. **Primitive tokens** — raw values with no usage meaning: a hex color, a
   pixel size, a millisecond duration. Primitives are versioned and
   immutable-ish: changing a primitive is a breaking change reviewed in an ADR.
2. **Semantic tokens** — named by purpose, not by value: `color-ink-primary`,
   `space-8`, `motion-duration-standard`. Semantic tokens reference primitives
   or carry them directly. Components consume semantic tokens only.

One source: `tokens/loom.toml`. Documentation (`DESIGN_TOKENS.md`,
`THEMING.md`) and generated Slint constants (`Tokens.slint`, generated by the
`loom-core` token generator in a later milestone) derive from it. See
`docs/adrs/ADR-0001-design-tokens.md` for the decision record.

## 2. Naming convention: `category-role-scale`

Every token name is lowercase-with-hyphens and has three segments:

* **Category** — `color`, `space`, `radius`, `border`, `type`, `motion`,
  `shadow`, `icon`.
* **Role** — the semantic job: `surface`, `ink`, `accent`, `status`, `size`,
  `leading`, `weight`, `duration`, `easing`, `width`, `viewbox`, `stroke`.
* **Scale** — the value label: the numeric step (`8`, `20`), the mnemonic
  (`primary`, `fast`, `out-quad`), or both where meaningful.

Examples: `color-surface-canvas`, `space-8`, `radius-4`, `border-width-default`,
`type-size-14`, `type-weight-semibold`, `motion-duration-fast`,
`motion-easing-out-quad`, `icon-viewbox-20`, `icon-stroke-width-15`.

Rules:

* Only categories and roles in this document exist. Inventing one is an ADR.
* The scale segment is the numeric value in px/ms when one exists
  (`space-8` = 8 px), a mnemonic when it does not (`color-ink-primary`), and
  ×10 for fractional values (`icon-stroke-width-15` = 1.5 px) — documented in
  the table below.
* Theme variants (light/dark/high-contrast) are values of the same token, not
  different tokens. `color-surface-canvas` exists in all three themes with
  different values.

## 3. Mapping to Slint constants

The generator emits a `Tokens.slint` file declaring every semantic token as an
`export const`, grouped in structs per theme. Naming in Slint is identical to
the TOML keys; Slint identifiers already allow dashes.

```slint
// generated from tokens/loom.toml — do not edit by hand
export struct PaletteTokens {
    surface-canvas: color,
    // ...
}
export const light-palette: PaletteTokens = {
    surface-canvas: #faf9f7,
    // ...
};
export const space-8: length = 8px;
export const motion-duration-fast: duration = 120ms;
export const motion-easing-out-quad: easing = cubic-bezier(0.33, 1.0, 0.68, 1.0);
export const type-size-14: length = 14px;
```

Applications bind themes at runtime by selecting the theme struct (see
`THEMING.md`); they never hard-code a literal color, size, or duration.
Sizes and durations are emitted in their native Slint types (`length`,
`duration`, `easing`) so misuse is a compile-time error.

## 5. Spacing

Scale in px: `space-2` 2, `space-4` 4, `space-6` 6, `space-8` 8, `space-12` 12,
`space-16` 16, `space-20` 20, `space-24` 24, `space-32` 32, `space-40` 40,
`space-48` 48, `space-64` 64.

Usage mapping: 2 internal hairlines, 4 dense control insets, 6 compact gaps,
8 standard gap, 12 control-to-control, 16 panel padding, 20 section spacing,
24 card/window padding, 32+ page-level grouping. See `SPACING.md`.

## 6. Radii

`radius-2` 2, `radius-4` 4, `radius-6` 6, `radius-8` 8, `radius-12` 12 px.

Mapping: 2 chips/tags, 4 small controls and inputs, 6 standard buttons and
cards, 8 dialogs and larger panels, 12 media wells and large surfaces.

## 7. Border widths

`border-width-hairline` 1 px, `border-width-default` 1 px,
`border-width-strong` 2 px. Hairline is used for dividers inside panels;
default for control outlines and panel edges; strong for focus rings and
emphasized grouping (2 px strong == `space-2`).

## 8. Type

Sizes (px): `type-size-11`, `type-size-12`, `type-size-13`, `type-size-14`,
`type-size-16`, `type-size-20`, `type-size-24`, `type-size-32`,
`type-size-40`.

Leading ratios: `type-leading-compact` 1.4 (headings, dense UI),
`type-leading-body` 1.45 (default body), `type-leading-relaxed` 1.5 (long-form
text, small sizes).

Weights: `type-weight-regular` 400, `type-weight-medium` 500,
`type-weight-semibold` 600, `type-weight-bold` 700.

Usage roles: caption 11, small 12, ui-label 13, body 14, body-large 16,
subtitle 20, heading 24, display-1 32, display-2 40. See `TYPOGRAPHY.md`.

## 9. Motion

Durations (ms): `motion-duration-instant` 0, `motion-duration-fast` 120,
`motion-duration-standard` 200, `motion-duration-deliberate` 320,
`motion-duration-slow` 500.

Easings (cubic-bezier control points):
`motion-easing-out-quad` (0.33, 1.00, 0.68, 1.00) — default entrance and
state change; `motion-easing-in-out` (0.65, 0.00, 0.35, 1.00) — value changes
and cross-fades; `motion-easing-out-back` (0.34, 1.56, 0.64, 1.00) — spring-ish
feel, used sparingly for panel entrances where a slight overshoot communicates
"arrived". See `MOTION.md` for the grammar and reduced-motion rules.

## 10. Shadows

Loom is flat by principle: `shadow-none` (no shadow, no elevation) is the
default for all surfaces — depth comes from color steps between canvas,
raised, and sunken. The single exception: `shadow-popover`
(`0 1px 3px rgba(38, 34, 28, 0.12)`) for popovers, menus, and tooltips that
must separate from the surface beneath. No glow, no colored shadows.

## 11. Icon grid

`icon-viewbox-20` 20 px, `icon-stroke-width-15` 1.5 px, `icon-corner-radius-2`
2 px, per the optical alignment rules in `ICONOGRAPHY.md` (alignment guides at
the 0, 20, 40, 60, 80, 100% marks of the 20 px viewBox).

## 12. Data visualization

Categorical series palette (values valid in both themes; charts must provide
≥ 3:1 against their plot background): terracotta `#B4552D`, teal `#2E7D6E`,
ochre `#C98A2E`, slate `#4A6B8A`, plum `#7A5C8A`, moss `#6B8A4A`. See
`COLOR.md` §6. Max 6 categorical colors before grouping; never use
`color-accent-default` and terracotta together in one chart.

## 13. Token governance

* Add a token: TOML + both documents + ADR, one change.
* Change a value: same, with a rationale that references the accessibility
  floor it respects.
* Delete a token: update every reference in this repository and applications;
  deprecate for one release cycle first.
* Application code must compile against the generated constants; any token
  referenced but missing in `loom.toml` is a build error.
